## 3-1. 「分析」機能を担う探索内の手法の種類

### 探索レポートの代表的手法一覧

- **① データ探索（自由形式）**: ディメンションや指標などを組み合わせて様々なレポートを作成・閲覧できる。
- **② コホート分析**: コホート対象者・リピート条件を決め、ある期間に戻ってきた人を蓄積して表示することで（ユーザーの）継続率・定着率を測定する。
- **③ 目標到達（達成）プロセス分析**: 自分でチェックポイント（ファネル）を追加して、どのような経路をたどったか、自由にステップを設定し、遷移率を確認できる。シーケンス（段階ごとの条件指定）プロセスの確認。ステップは「`page_view`」のみでなく「`click`」や「`file_download`」などユーザーにとってほしいイベントの設定も可能。
- **④ セグメントの重複**: セグメントを最大3つまで設定でき、重複も確認できる。たとえば「モバイル」「direct（ノーリファラー）」「25〜34歳」という3つの指標を設けた場合、それぞれ重複率や人数が可視化される。（UAではそれぞれ個別に見る必要があった）
- **⑤ 経路の分析**: ページやイベントの遷移の内訳を見ることができる。ページ単位の行動フローだったUAと異なり、GA4ではイベント単位での（遷移）内訳を確認できるため細やかな導線計測が可能。CV（終点）から逆引きで、どのような経路をたどったかも閲覧できる。
- **⑥ ユーザー エクスプローラ**: 概要・仕様はUAと同じ。
- **⑦ ユーザーのライフタイム**: ユーザー軸で見た滞在時間やセッション回数などを閲覧でき、購買（CV）に結びついたものなどについても長い期間で把握することができる。

## 3-2. 目標到達プロセスデータ探索 & オススメ探索設定例①時系列レポート

### 探索レポート・機能: 「目標到達プロセスデータ探索」

サイトのどのページでユーザーが離脱しているかや指定したページ別の遷移率や、指定したページごとのステップ率（ユーザー数）を把握できる。  
GA4で計測しているデータをチェックポイントとして設定し、各チェックポイントの通過率を確認できる。チェックポイントはページだけに限らず、計測しているイベント名やイベントパラメータも指定できる（例: ファイルDLなど）。  
**確認指標:** 放棄率・放棄数、完了率

#### 条件の設定で出てくる「次の直接的ステップ」と「次の間接的ステップ」の違い
- **直接的**: ページA → ページB（指定したルート通りである必要がある）
- **間接的**: ページA → ページD → ページC → ページB（最終的に達成していればOK）

#### 設定例
- **ステップ**: サイトでユーザーに辿ってほしい行動を設定（特定ページ閲覧、ファイルDLなど）。例: TOPページ → DLページ → ファイルDL
- **内訳**: デバイスやチャネルグループなど
- **用途**: 主要導線の母数と落ちている（離脱している）ポイントを把握する。内訳ごとに遷移率に違いがないかをチェックする。施策実施の前後の日付で変化を見る（遷移率の違い）。

### ☆オススメの探索レポート設定例

#### ① 時系列レポート
- **ディメンション**: 日付
- **指標**: アクティブユーザー数 / 新規ユーザー / リピーター数 / セッション / エンゲージメント率 / CV数 / セッションのCV率（必要に応じて）
- **用途**:
  - 時系列で数値の変化（特異点: 急激な数値の増減）を見つける。
  - 全指標が変化しているのか、特定指標が変化しているのか。
  - 変化の原因を特定するためディメンションをさらに追加して深掘りも可能。

## 3-3. オススメ探索レポート設定例②集客レポート & ③初回獲得エンゲージメントレポート

### ② 集客レポート

- **ディメンション**: セッションのデフォルトチャネルグループ / セッションの参照元またはメディア
- **指標**: アクティブユーザー数 / セッション / エンゲージメント率 / セッションあたりのエンゲージメント / CV / セッションのCV率
- **ネストされた行**: Yes（ディメンションごとにまとめて見やすい形で表示してくれる。複数項目を端的にチェック・把握したい場合に有用）
- **用途**:
  - 流入元の特徴を発見する。
  - エンゲージメント率やセッションあたりのエンゲージメントが高い回遊につながっている流入元を特定する。
  - 日付のディメンションを追加して数値の変化を見つける。

### ③ 初回獲得エンゲージメントレポート

- **ディメンション**: 最初のユーザーのデフォルトチャネルグループ / 最初のユーザーの参照元/メディア
- **指標**: アクティブユーザー数 / リピーター数 / ユーザーあたりのセッション数 / エンゲージメント率 / CV / ユーザーCV率
- **ネストされた行**: Yes
- **用途**:
  - 新規獲得につながった流入元、またそこからリピート訪問につながった流入元を特定。
  - ユーザーエンゲージメントはユーザー数と別途割り算して1人あたりの滞在時間を出す。
  - 初回流入元とCVの関係性を見る。

## 3-4. オススメ探索レポート設定例④入口・出口 ⑤コンバージョン ⑥外部リンククリック

### ④ 入口・出口レポート

- **ディメンション**: ページ階層とスクリーンクラス
- **指標**: PV数 / 閲覧開始数 / 離脱数 / ユーザーあたりのビュー
- **セグメント**: CVユーザー等にしぼり込む（必要に応じて）
- **用途**:
  - 「入口 ＜ 出口」となっているページは、出口となっても問題ないページかどうかを探る（aboutページなど）。
  - 閲覧開始数 ÷ PV数 で閲覧開始率を見る。
  - 離脱数 ÷ PV数 で離脱率を見る。

### ⑤ コンバージョンレポート

- **ディメンション**: イベント名 / セッションのデフォルトチャネルグループ
- **指標**: 利用ユーザー / CV / ユーザーあたりのイベント数
- **フィルタ**: コンバージョンイベント = true にしておく（ディメンション選択時に「コンバージョンイベント」を追加するとフィルタで利用できる）
- **用途**:
  - それぞれのCVの発生回数を確認。
  - 流入元などと掛け合わせて内訳や特徴を発見していく。
  - 1ユーザーあたりのCV発生回数が多いイベントはあるかどうかを探る。

### ⑥ 外部リンククリックレポート

- **ディメンション**: ページ階層とスクリーンクラス / リンク先URL
- **指標**: イベント数
- **フィルタ**: イベント名 = `click` に
- **用途**:
  - どのページから外部リンクに遷移しているのか、外部リンクの飛び先として多いリンク先はどこか。
  - PV数と割り算してクリック率を算出する。

## 3-5. オススメ探索レポート設定例⑦ファイルDL & ⑧コンバージョン直前ページ逆引き

### ⑦ ファイルダウンロードレポート

- **ディメンション**: ページ階層とスクリーンクラス / リンク先URL / リンクテキスト
- **指標**: イベント数
- **フィルタ**: イベント名 = `file_download` に
- **用途**:
  - どのページからファイルダウンロードされているのか。
  - 人気が高いファイルはどれか。
  - PV数と割り算してクリック率を算出する。

### ⑧ コンバージョン直前ページ逆引きレポート

**「経路データ探索」**を使用。CVの入口（問い合わせフォームなど）を**終点**として設定し、その手前の動きを見ていく（終点 ⇔ 始点を入れ替えることで順引きの計測・把握も可能）。

- **用途**:
  - 終点（CVへの入口）や始点（トップや特定LP）を指定する。
  - どこから来て、どこに向かっているか上位の順位（経路）を確認する。
  - どの遷移を強化するか決めて、施策の実施後に比較評価を行う。
