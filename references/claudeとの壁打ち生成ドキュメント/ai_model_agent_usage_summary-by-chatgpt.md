# AIモデル・AIエージェントの利用経路：超シンプル整理

## 前提：「モデル」と「AIツール」は別

まず、話を整理するうえで最も基礎となる区別が「モデル」と「AIツール（AIエージェントツール）」は別物である、という点。

例えば、

- Claude = モデル
- Gemini = モデル
- GPT = モデル
- Claude Code = AIエージェントツール
- Claude Cowork = AIエージェントツール
- Antigravity = AIエージェントツール

というイメージ。

以降では「あるAIツールから、あるモデルをどう利用するか（＝利用経路）」を整理する。

## 結論（3つの利用経路）

モデルの利用経路は、大きく次の3つに分けられる。

- **API契約** → 各AIツールから対応するモデルを利用できる。基本は**従量課金**。
- **クラウド経由** → Google Vertex AI / AWS / Azureなどを経由して、対応するモデルを利用できる。基本は**従量課金**。
- **サブスク契約**（Claude Pro/Max、ChatGPT Plus/Pro、Google AI Plus/Pro/Ultraなど）→ **そのサブスクの利用枠を、別のAIツールやAPIに持ち込むことは基本できない**。

以降、それぞれの経路を詳しく見ていく。

## Google Vertex AI とは

上記「クラウド経由」の代表例が Google Vertex AI なので、先に押さえておく。

Google Vertex AIは**Google CloudのAIプラットフォーム**。

Google製だが、GoogleのGeminiだけでなく、対応する他社モデルも扱える。

```text
Google Vertex AI
 ├─ Gemini
 ├─ Claude
 └─ その他の対応モデル
```

## API / クラウド経由

モデルを別のAIツールから使う場合は、例えば：

```text
自分のAIツール
   ↓
Claude API
   ↓
Claude
```

または、

```text
自分のAIツール
   ↓
Google Vertex AI
   ↓
Claude
```

のように利用できる。

この場合は、**API / クラウド側の契約・課金**になる。

## サブスク経由

例えば、

```text
Claude Max
   ↓
Claude Code / Claude Cowork
```

のように、Anthropicが提供する対応製品を使う。

一方、

```text
Claude Max
   ↓
別のAIツール
   ↓
Claude API
```

のように、**Claude Maxの利用枠をAPIとして別ツールに持ち込むことは基本できない**。

同様に、

```text
ChatGPT Plus / Pro
   ↓
別のAIツール
   ↓
OpenAI API
```

として、ChatGPTのサブスク枠をAPI利用に流用することも基本できない。

## 具体例：Antigravity のケース

ここまでの整理を踏まえて、Antigravity（GoogleのAIエージェントツール）が他社モデルを扱えるケースを見ておく。

> [!NOTE]
> Antigravity が Gemini 以外に Claude（Anthropic）や GPT-OSS（OpenAIのオープンウェイトモデル）などを**「ビルトイン（組み込み）」で選択・利用できる**のは、Google が `Google Vertex AI` のような他社モデルも扱えるAIプラットフォームを自社で持っているためと考えられる（※提供経路の詳細は公式には明言されていない）。なお、搭載されているのは OpenAI の**オープンウェイトモデル（GPT-OSS）**であり、`ChatGPT`（GPT-5系などのプロプライエタリ製品）そのものではない点に注意。  
> 他のLLMベンダー（Anthropic, OpenAI）は同種のマルチモデル・プラットフォームを提供していないため、**現状では前述のAPI経由以外で他社モデルを組み込むことは基本的にできない**。

### 利用ルートの整理（参考意見・壁打ちメモ）

> [!NOTE]
> 以下は本トピックの壁打ちで得られた理解の整理（参考意見）。公式ドキュメントで確認済みの事実と、そこからの解釈を区別して記載する。
> - Models: https://antigravity.google/docs/models/

- **アカウント（サブスク）ログインで使うルート**：Google AI の消費者向けプラン（Free / AI Plus / Pro / Ultra）でログインすると、Antigravity 側が Claude や GPT-OSS を「組み込み（ビルトイン）」で提供する。**ユーザーが自分で Anthropic / OpenAI と契約する必要はない**（これが「組み込みで使える」の実態）。
  - ※注意：**Enterprise（法人・GCP 経由）プランでは他社モデルは非提供（Gemini のみ）**。他社モデルが使えるのは消費者向けプラン側であり、「企業プランだから他社モデルが使える」わけではない（公式 Models ページの Enterprise 列は ❌）。
- **従量課金でスケールさせたいルート**：Antigravity IDE の外で、自前のアプリ等から従量利用・スケールさせたい場合は、**Vertex AI API や各社 API を自分で契約するルート**になる。
  - ※注意：Vertex AI 経由で使える "OpenAI系" は **GPT-OSS（オープンウェイトモデル）まで**であり、`ChatGPT`（GPT-5 系などのプロプライエタリ本体）は **OpenAI API 直**が必要。Claude は Vertex AI（パートナーモデル）でも Anthropic API 直でも従量利用可能。

## 補足：オーケストレーション（ツール連鎖）という応用

上記3経路とは別に、「あるAIツールから、別のAIツールをシェル経由で起動する」という**オーケストレーション（ツール連鎖）**の形も技術的には成立し得る。

例えば、Claude Code（Anthropic）や Codex（OpenAI）のような CLI エージェントから、Antigravity CLI（`agy`）のヘッドレスモードを呼び出してプロンプトを渡し、実行させる、といった構成。

```text
Claude Code（Claude Max / API で認証・課金）
   ↓ シェルで別CLIをヘッドレス起動
Antigravity CLI（agy / Google 側で"独立に"認証・課金）
   ↓
Gemini / Claude(via Vertex) / GPT-OSS など
```

> [!NOTE]
> これは**「サブスク枠の持ち込み」ではない**点に注意。内側のツール（`agy`）は Antigravity 側の認証・課金で動くため、「Claude の枠で他社モデルを呼ぶ」わけではなく、「独立に認証された2つのツールを数珠つなぎにしているだけ」。したがって前述の「サブスク枠は別ツールに持ち込めない」という原則は破られていない。あくまで **API / クラウド / サブスクという3経路の"上に乗る"連携の形**である。
>
> （一次情報での確認：公式ドキュメント `antigravity.google/docs/cli/...` に Antigravity CLI（`agy`）および Headless Mode の存在を確認済み。認証の詳細は同 Installation & Auth ページを参照のこと。）

### コントロール面の懸念（重要）

この構成には、安全管理（ガバナンス）上の看過できない懸念がある。**利便性だけで採用を判断してはならない。**

- **ガードレールの跨ぎ**：呼び出し元（例：Claude Code）のフック（`PreToolUse` など）・権限設定（`permissions`）・事前承認（HITL）は、**呼び出し元ランタイムの管轄内でしか強制されない**。シェルで内側の CLI を起動した瞬間、内側エージェントの挙動は呼び出し元の安全機構の**管轄外**になる。
- **「憲法を置く」だけでは不十分**：内側にも同型のハーネス（`GEMINI.md` など）を持たせれば緩和はできるが、それは指示レベルの拘束にとどまる。**内側 CLI 自身が実行時強制（`PreToolUse` 相当のフック等）を備えて初めて**、呼び出し元と同等の安全性になる。「ハーネスの有無」ではなく「**実行時強制の有無**」が実効性の分かれ目。
- **自律の二重化と監視の希薄化**：自律エージェントの内側でさらに自律エージェントを動かすため、人間の監視（HITL）が届きにくくなる。コストも両ツール分が二重に発生する。

> [!CAUTION]
> よってこの経路を採る場合は、**内側 CLI の実行時強制機構・認証境界・HITL の跨ぎ方**を事前に設計・検証すること。これらが担保できないまま自律エージェントをシェルから放つことは、本来のガードレールを実質的に無効化する行為になり得る。

## まとめ（最重要ポイント）

**サブスクとAPIは別物。**

- サブスク → その会社が提供する対応サービスを使う
- API / クラウド → モデルを別のAIツールから利用できる
- API / クラウドの利用は基本的に従量課金
- サブスクの利用枠を、そのまま別ツールのAPI利用に持ち込むことは基本できない

### 一言で

> **「Claude Maxを持っているからAntigravityでClaudeを使える」ではなく、「Antigravity側がClaudeを提供しているから使える」。**
>
> **「自分でClaude APIを契約すれば、対応する別AIツールからClaudeを使える」。**
